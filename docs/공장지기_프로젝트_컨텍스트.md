# 공장지기 프로젝트 컨텍스트 문서

> 이 문서는 AI 에이전트(Claude, GPT, Gemini 등)에게 프로젝트의 전체 맥락을 전달하기 위한 핸드오프 문서입니다. 이 문서와 함께 첨부된 기획서 PDF/PPTX를 함께 참조하면 새로운 세션에서도 흐름을 이어갈 수 있습니다.

## 0. 에이전트에게 주는 지시

당신은 사용자와 함께 "공장지기" 프로젝트의 해커톤 기획서를 다듬어 온 협업 파트너입니다. 이 문서를 읽고 다음을 이해해주세요.

1. 프로젝트의 현재 상태 (1~3장)
2. 그동안 내려진 주요 의사결정과 그 이유 (4장)
3. 명시되지 않은 암묵적 가정 (5장)
4. 사용자가 자주 묻는 질문 패턴 (6장)
5. 다음에 다룰 만한 작업 후보 (7장)

사용자는 한국어로 소통합니다. 응답도 한국어로 해주세요. 사용자는 이미 프로젝트 맥락을 알고 있으므로 처음부터 다시 설명할 필요는 없으며, 사용자가 언급한 부분에 집중해서 답변해주세요.

## 2. 프로젝트 개요 — 공장지기

### 한 줄 정의

설비 센서 데이터로 잔여수명(RUL)과 72시간 내 고장 위험도를 추정하고, 그 근거를 매뉴얼 기반 정비 작업지시서로 변환해 작업자에게 전달하는 중소 제조사 전용 AI 운영 플랫폼.

### 팀명·프로젝트명

- 팀명: **공장지기**
- 프로젝트명: **공장지기 (잔여수명·정비지시 플랫폼)**

### 페르소나 (가상 인물)

- **김영수 반장**, 48세, 생산팀장 12년차
- 근무지: 경기도 시흥시 시화공단, 종업원 25명 자동차 부품 사출성형업체
- 담당: 사출기 8대 (1996~2018년식 혼재) + 보조 설비
- 도구: 스마트폰(카톡), 사무실 공용 PC 1대, 종이 점검표
- KPI: 월 가동률 95% 이상, 납기 지연율 2% 이하

> **중요**: 김영수 반장은 가상 인물입니다. 실제 인터뷰가 아닙니다. 본선 발표에서 "실제 인터뷰인가?"라는 질문이 나오면 "산업계 통계와 페르소나 모델링을 결합한 시나리오"라고 답해야 합니다.

### 시나리오 (페르소나의 4월 한 달 사건)

1. 4/8 03:22 — 3호 사출기 유압 펌프 고장. 36시간 비계획 정지
2. 4/12 — 고객사 납기 지연 페널티 800만 원 청구
3. 4/15 — 베테랑 정비기사 박씨(57세) 퇴사 통보
4. 4/22 — 신입 작업자에게 모호한 지시("3호기 그리스 좀 봐줘")

> **중요**: 36h, 800만원, 12년 등 수치는 시나리오 가정값입니다. 실제 측정값이 아닙니다.

## 3. 기술 구조

### 3-모듈 폐쇄 루프

| 모듈 | 역할 | 입력 | 처리 | 출력 |
|---|---|---|---|---|
| **A. 추정** | 센서 → RUL·위험도 | 진동·온도·전류 다변량 시계열 (윈도우 50사이클·21변수) | 딥러닝 회귀 + 분류 (2개 모델 병렬) | RUL·신뢰구간·위험도(%)·근거 센서, 알림 트리거 |
| **B. 지시** | RUL → 작업지시서 | RUL + 설비 사양 + 매뉴얼 + 과거 이력 | Gemini API + RAG | 표준 양식 정비 지시서 |
| **C. 축적** | 결과 → 재학습 데이터 | 정비 완료 결과 (성공/실패, 교체 부품) | DB 적재 + 재학습용 라벨 데이터 생성 | 월간 노하우 리포트, 재학습 가능한 데이터셋 |

### 데이터 흐름 8단계

센서수집 → TS저장 → RUL추정 → 결과저장 → 지시생성 → 사용자알림 → 결과입력 → 학습적재

### 기술 스택

| 레이어 | 기술 | 선택 이유 |
|---|---|---|
| 프론트엔드 | React + Tailwind + Recharts | 대시보드 시각화 최적, 빠른 프로토타이핑 |
| 백엔드 | FastAPI (Python) | ML 모델과 동일 언어, 비동기 처리 |

### AI #1 (시계열 예측 + 고장 진단)

분석가 피드백 반영 후 **2개 모델 병렬 추론 구조**로 정의됨.

**모델 1: RUL 회귀 (잔여수명 추정)**
- 학습 데이터: **NASA C-MAPSS** (Commercial Modular Aero-Propulsion System Simulation)
  - 출처: NASA Prognostics Center of Excellence (PCoE), 2008 PHM Data Challenge 표준 벤치마크
  - 성격: **시뮬레이션 데이터** (실제 엔진 비행 데이터 아님). NASA의 물리 기반 시뮬레이터가 정상→열화→고장 과정을 가상 생성. 센서 노이즈 포함.
  - 권위: 1,000편 이상의 논문에서 검증된 RUL 예측 분야 표준
- 사용 서브셋: **FD001** (단일 운전조건·단일 고장모드, 학습 100엔진 + 테스트 100엔진)
- 데이터 구조: 26컬럼 (엔진번호 + 사이클 + 운전조건 3 + 센서 21)
- 21개 센서: **온도·압력·회전속도·유량 중심** (진동 센서 없음 → AI Hub로 보완)
- 파일 구성: train_FD001.txt (run-to-failure) / test_FD001.txt (고장 전 절단) / RUL_FD001.txt (정답)
- 모델 후보: LSTM 베이스라인 → 1D-CNN+LSTM → Transformer (LSTM 우선 확보)
- 출력: RUL 값(사이클), 신뢰구간
- 평가 지표: RMSE ≤ 20 cycles 목표, PHM Score Function
- 사이클→시간 변환: 1사이클 ≈ 1시간 가정 (현장 적용 시 설비별 보정)
- **역할**: RUL 회귀 알고리즘 검증

**모델 2: 고장 유형 분류 + 근거 센서 식별**
- 학습 데이터: **AI Hub 「기계시설물 고장 예지 센서」** (데이터셋 번호 238)
  - 출처: 대전광역시 도시철도공사 역사 3개소
  - 대상: 송풍·환기용 전동기 41대 (12종 용량)
  - 규모: 진동·전류 데이터 총 233.3만 개 (정상 109.8만 + 고장 123.5만)
- 분류 대상: 5종 상태 (정상 + 4종 고장: 베어링 불량, 회전체 불평형, 축정렬 불량, 벨트 느슨함)
- 모델: 1D-CNN 분류기
- 출력: 고장 유형 확률, 근거 센서(Feature Importance/Attention)
- **역할**: 한국 산업 환경 회전체 진동·전류 패턴 학습 (사출기 유압펌프=회전체이므로 도메인 부분 전이 가능)
- **추가 한계**: AI Hub 데이터는 상시 정속 운전 모터, 사출기는 사이클별 부하 변동 큼 → 부하 패턴 차이는 Phase 1 파일럿에서 보정

**두 모델의 통합**:
- 동일 센서 입력에 두 모델 병렬 실행
- 모델 1 → "RUL 72h(±24h)"
- 모델 2 → "베어링 불량 78%, 근거 센서: 진동 RMS, 모터 전류"
- 통합 출력을 LLM에 전달 → 정비 지시서 생성

**중요한 한계 인정**:
- C-MAPSS는 항공 엔진, AI Hub는 도시철도 송풍·환기 모터. 둘 다 사출기 도메인이 아님.
- 추가로, AI Hub 모터는 상시 정속 운전이고 사출기는 사이클별 부하 변동이 큼 → 부하 패턴 차이 존재.
- MVP는 알고리즘 작동 검증 단계. 실제 사출기 적용은 Phase 1 파일럿 데이터로 도메인 보정 필수.
- 본선 답변: "한계를 알고 있고, Phase 1 로드맵의 경기도 3사 무상 파일럿이 이 보정 작업"

### AI #2 (LLM + RAG)

- 모델: Gemini API (MVP는 무료 티어, 사업화 단계에서 유료 전환)
- RAG 지식베이스: 설비 매뉴얼 PDF + 과거 정비 이력 DB + 사내 SOP 문서
- 출력 양식: 점검 부위, 사용 도구·소모품, 소요시간, 안전수칙, 체크리스트

### MVP 스코프

**포함**:
- 웹 대시보드 5종 (메인 / 설비 상세 / 지시서 / 결과 입력 / 노하우 리포트)
- 추정 모듈 2종 (RUL 회귀 + 고장 분류, NASA C-MAPSS·AI Hub 학습)
- 가상 센서 시뮬레이터 (CSV 스트림)
- LLM 기반 지시서 자동 생성 (RAG 적용)
- 정비 이력 DB + 결과 입력 폼
- 카카오톡 알림 (웹훅 또는 데모용 모달)
- 샘플 매뉴얼 PDF 3종 RAG 인덱싱

**제외 (의도적 컷)**:
- 실제 IoT 센서 하드웨어 연동 (시뮬레이터 대체)
- 다중 사용자 권한 관리
- 모바일 네이티브 앱
- 모델 자동 재학습 파이프라인 (수동 트리거)
- 다국어, 다중 공장 멀티테넌시
- 외부 ERP / MES 연동
- 실시간 OPC-UA 통신

### 시연 시나리오 (5분)

1. 0:00~0:30 — 메인 대시보드 진입 (3호기 빨간 "주의" 표시)

3. 1:30~2:30 — 지시서 (AI #2 출력: 버튼 클릭 → 5초 내 LLM 생성 지시서 + 매뉴얼 출처)
4. 2:30~3:00 — 작업자 전송 (카톡 발송 모달)
5. 3:00~4:00 — 결과 입력 (정비 완료 폼 → 학습 큐 적재)
6. 4:00~5:00 — 노하우 리포트 (월간 누적 리포트 → 데이터 기반 의사결정 지원)

| 지표 | 수치 | 산출 근거 |

### 로드맵

- **PHASE 1** (~2026 Q3): MVP 고도화. 경기도 시화·반월 중소 3사 무상 파일럿
- **PHASE 2** (2026 Q4 ~ 2027 Q2): 베타 + 파일럿 확대. 경기도 20개사 유료 베타. **LLM API 유료 전환 + 비용 최적화**
- **PHASE 3** (2027 Q3 이후): 정식 SaaS + 전국 확장. 중기부 스마트공장 보급사업 공급기업 등록

## 4. 주요 의사결정 이력

### 결정 1: 컨셉 선택 — "예지보전 + 작업지시 통합"

**고려한 대안**:
- A. 품질관리 어시스턴트 (스마트폰으로 불량 검출)
- B. 예지 보전 + 작업 지시 통합 ← **선택**
- C. AI Agent 기반 생산계획 코파일럿

**선택 이유**: 평가 기준의 "유기적 연결"과 "실질적 기여"를 동시에 만족. 데이터 흐름이 자연스러운 폐쇄 루프 구성. NASA C-MAPSS 같은 공개 데이터로 D-15 안에 프로토타입 가능.

### 결정 2: LLM 선택 — "Gemini API 무료 티어"

**의사결정 흐름**:
1. 처음 — Claude API 검토
2. 사용자 지적 "Claude API는 비용 발생" + Claude Code 구독은 자체 앱 API 호출 권한이 아님 확인
3. Ollama + Qwen3 8B 로컬 LLM 검토 → 사용자가 다른 옵션 요청
4. **Gemini API 무료 티어로 최종 결정**

**선택 이유**:
- 무료 티어 (2.5 Flash-Lite 기준 일 1,000회, 분당 15회) — 시연·개발에 충분
- 신용카드 불필요, 만료 없음
- 한국어 우수
- "MVP 무료 → 사업화 유료 전환" 스토리가 자연스러움
- 시연 중 라이브 호출 가능 (사전 캐시 불필요)

### 결정 3: 양식 활용 방식

**제약**: 대회 양식의 틀 반드시 유지

**해결**: 양식의 헤더·외곽박스·푸터·로고는 그대로 두고, 안내 문구 박스만 삭제 후 외곽 박스 안에 우리 콘텐츠를 도형/표/텍스트로 추가. python-pptx로 정밀 편집.

### 결정 4: 시뮬레이터 방식

**문제**: 실제 사출기 센서 데이터를 D-15 안에 모을 수 없음

**해결**: NASA C-MAPSS의 한 엔진 트랙(시계열 CSV)을 1초마다 한 사이클씩 백엔드로 POST하는 Python 스크립트. 시연용 시나리오 3종(정상/경고/위험) 사전 준비.

### 결정 5: 페르소나 — 가상으로 가되 구체적으로

**원칙**: 실제 인터뷰가 아니어도 페르소나는 매우 구체적으로(이름, 나이, 회사 위치, 사용 도구) 그려야 평가 기준의 "구체적 설정" 점수에 답할 수 있음.

### 결정 6: 표현 정밀화 — "고장 시점 예측" → "잔여수명 + 위험도 추정"

**배경**: 외부 AI 분석가 피드백을 반영. PdM(예지보전) 도메인은 본질적으로 확률·구간 표현을 사용해야 정확함.

**변경 사항**:
- 한 줄 정의: "고장 시점을 예측" → "**잔여수명(RUL)과 72시간 내 고장 위험도를 추정**"
- 모듈 명칭: "예측 모듈" → "**추정 모듈**", "학습 루프" → "**축적 모듈**"
- 폐쇄 루프 표현: "쓸수록 똑똑해진다" → "**재학습 가능한 데이터 축적**"
- 시연 출력 형태: "RUL 72h" → "**RUL 72h(±24h) / 위험도 78% / 근거 센서 3종**"
- 데이터셋 활용: 두 데이터셋의 역할을 분리 명시 (RUL 회귀 vs 고장 분류)
- 평가 지표: RMSE 외에 **고장 미탐률 ≤ 10%, 불필요 정비율 ≤ 15%** 운영 지표 추가
- 사이클→시간 변환: 1사이클 ≈ 1시간 가정 (현장 적용 시 설비별 보정) 명시

**선택 이유**: 본선 발표에서 PdM 전문가 심사위원의 기술 검증 질문(특히 "AI가 고장 시점을 정확히 맞히나요?")을 정면 방어하기 위함. 표현이 정확해야 가산점.

## 5. 명시되지 않은 암묵적 가정

다음은 기획서에 명시되어 있지 않거나 짧게만 표기되어 있는 사항들입니다.

1. **페르소나 김영수 반장은 가상 인물**. 실제 인터뷰 결과가 아님. 산업계 통계와 페르소나 모델링을 결합한 시나리오.

2. **수치는 모두 추정값**. 36h, 800만원, ↓50%, 연 4,800만원 등은 모두 가정·추정. 본선에서는 "MVP 완성 후 파일럿에서 실측 검증" 메시지로 풀어가야 함.

3. **기획서의 자기 평가 매핑은 의도적 설계**. 각 슬라이드가 평가 항목 어디에 매칭되는지 사전에 역산해서 배치. 예: 슬라이드 5 = AI 활용 25점, 슬라이드 7 = MVP 구현 25점.

4. **2인 팀 가정으로 일정 설계**. 팀원 A(AI·백엔드), 팀원 B(프론트·기획)로 D-15 일정 짜둠.

5. **"플랫폼"의 정의**: 화면이 여러 개라는 의미가 아니라, 한 사용자(김반장)의 의사결정 사이클이 시스템 안에서 완결되는 폐쇄 루프 구조. 이 정의가 평가 기준의 "유기적 연결"에 직접 답함.

6. **카카오톡 알림은 데모용**: 실제 카톡 비즈메시지 API 연동이 아니라, 프론트엔드 모달로 "카톡 메시지 미리보기" 시연.

7. **"중소사 진입장벽 최소화"가 사업성 핵심 메시지**: 응모 자격이 "경기도 + 7년 이내 중소기업"이라는 점에 대응하는 의도적 포지셔닝.

## 6. 사용자가 자주 묻는 질문 패턴

새 세션에서 사용자가 다음과 같은 질문을 할 가능성이 높습니다. 답변 방향을 미리 알아두면 빠르게 대응 가능합니다.

### Q. "X가 정확히 뭐야?"

기술 용어 설명을 자세히 요청. 사용자는 비전문가가 아니지만, 본선 발표 대비 + 본인 이해를 위해 정확한 정의를 원함. 답변은 "쉬운 비유 + 정확한 정의 + 우리 프로젝트에서의 역할" 3단으로.

### Q. "Y는 어떻게 산출했어?"

수치의 근거를 물음. 솔직히 답할 것 — "이건 가정값/추정값이고, 본선에서는 실측 검증 메시지로 보강"이라고 명확히.

### Q. "Z 부분 수정해줘 / 의견 어때?"

매우 중요한 차이가 있음. **사용자는 "의견 요청"과 "반영 요청"을 명확히 구분**합니다. 헷갈리면 ask로 한 번 더 확인하는 게 안전. 과거에 의견만 물었는데 바로 반영해서 사용자가 불편을 표한 적 있음.

### Q. "이거 비용 들지 않아?"

비용에 민감. 이미 Gemini 무료 티어로 결정했으니, 추가로 비용이 발생할 만한 컴포넌트(클라우드 호스팅, DB, 외부 API)에 대해서도 무료/저비용 대안을 함께 제시.

### Q. "다른 옵션은 없어?"

특정 기술/방법으로 제한받기 싫어함. 대안을 폭넓게 제시한 후 권장안을 명시하는 방식 선호.
